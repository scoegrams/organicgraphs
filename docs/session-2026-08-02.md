# Session Notes — Aug 2 2026

A focused session on graph correctness, UX, and data hygiene.

---

## Graph identity: two GitHubs → one GitHub

**Problem:** The graph had both a `github (service)` and a `GitHub (vendor)` node — two nodes for the same thing.

**Fix:**
- Deleted the misclassified `github (service)` node (all its edges already existed on the vendor).
- Established the canonical model: **one GitHub vendor**, many `Repository` nodes per client.
  - `acme/web (repository)` → `repository_hosted_on_vendor` → `GitHub`
  - `apple/core (repository)` → `repository_hosted_on_vendor` → `GitHub`
- Added `product_has_repository` relationship to the software pack.
- Brain fan-out extended: when a repository is linked to a product, it auto-links to that product's existing vendors (and vice versa).

---

## Builder redesign: adding a developer in 2 steps

**Problem:** Adding a person to a project required scrolling to find "Person" in an alphabetical dropdown, then navigating a 5-step "Add connection" flow.

**Fix:**
- Replaced the TYPE dropdown with **type chips** — `Person | Feature | Product | Vendor | Service | Customer | More…`. Click once, done. Person is first by default.
- Name field auto-focuses on open.
- A single **"Link to project / product"** section replaces the multi-step "Add connection" row.
- Optional fields collapsed under `Optional fields ▸` — don't block the fast path.
- Save button disabled until name is non-empty.
- Added `person_member_of_product` relationship ("works on" / "has team member") — the correct semantic for a developer on a project, distinct from "invests in".
- `preferredTypesForAnchor("product")` now returns `[feature, person, vendor, service, ...]` — person at position 2.

## Sample company: 59 nodes → 11 nodes

**Problem:** "Add sample company" dumped 59 records (9 people, 12 vendors, 4 services, sprints, releases, deployments, incidents, decisions...) into the graph, creating a visual mess.

**Fix:** Replaced `softwareDemoDataset()` with a minimal 11-node, 15-edge dataset that teaches the structure without the noise:

```
Acme Corp (customer)
  └── client of → Developer Studio (product)
        ├── works on ← Sam Ortiz / Priya Nair / Alex Rivera
        ├── uses → Vercel / GitHub / Stripe
        ├── Checkout redesign → owned by Alex
        ├── Onboarding v2 → owned by Alex
        └── SSO / SAML → owned by Priya
```

The seeder remains idempotent — runs append safely, skipping existing nodes and edges by slug.

## Wizard auto-wiring: surgical, not promiscuous

**Problem:** The wizard seeder connected every person to every dev/comms/design tool (Cursor to all engineers), and every service to every monitoring tool — cross-products nobody approved.

**Fix:** Auto-wire only structural facts:
- `service → hosting vendor` ✓ (infra fact)
- `product → Payments / Email / Domain / Auth vendors` ✓ (load-bearing dependencies)

Not auto-wired (connect manually from the graph builder):
- `person → Cursor / Slack / Figma / Linear` — not every person uses every tool
- `service → Sentry / Datadog` — not every service has the same monitors
- `product → dev tools / comms / design` — Slack doesn't "power" the product

## Graph hover/select behavior

**Problem:** 2-hop neighborhood on hover lit up almost the entire graph in a small, dense workspace.

**Fix:**
- **Hover** → 1-hop only (node + direct connections). Quiet, informative.
- **Click/select** → same 1-hop. (2-hop was reverted — in a small graph it covers everything anyway. The inspector sidebar already shows all connections.)

---

## Unlink connections from the inspector

**New feature:** Hover any connection row in the node inspector → a `✕` appears on the right. Click it to delete that edge from the graph immediately.

- `deleteRelationship(orgId, edgeId)` server action with role guard + audit log.
- `edgeId` threaded from the graph payload through `selectedConnections` to the inspector.
- Invisible until hover, turns red on approach — clearly destructive but non-intrusive.

---

## Obsidian export: data-first vault

**Problem:** Export opened with `Schema — Record types.md`, `Schema — Relationship types.md`, and 4 other schema files before any real content. Relationship labels showed raw keys like `(investor_backs_product)` instead of readable text.

**Fix:**
- `Home.md` now opens with the actual company snapshot — every record grouped by type with its first connection shown inline.
- Record notes use human-readable labels: `[[bombs]] → is backed by` instead of `linked from [[bombs]] (investor_backs_product)`.
- Six schema files collapsed into one `_Schema.md` with tables.
- Manifest moved to `_schema/manifest.json`.
- Format bumped to `orggraph.obsidian-vault.v2`.
- `reverseLabel` passed through the export pipeline so incoming connections read naturally.
